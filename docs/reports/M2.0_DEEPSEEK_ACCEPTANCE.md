# M2.0 真实模型验收报告 — 小米 MiMo

> 本报告记录 CREA M2.0 AI Research Intelligence 的**第一次真实 LLM 驱动科研任务验收**。
> 模型为小米 MiMo（非 DeepSeek），通过 OpenAI Compatible Provider 接入。
> 报告中的每一个数字和每一条轨迹都来自实际运行记录 `data/m2-acceptance-run.json`，无事后补写。

---

## 0. 一句话结论

**CREA M2.0 的骨架是通的，但第一次真实验收暴露出一个使验收核心目标失效的架构缺陷：**

> 44 个工具的完整 JSON Schema 占 57577 字符，远超 24000 字符的状态预算；
> `render_state` 的截断循环只删 `observations`/`decisions`/`facts`，**不删 `available_tools`**，
> 因此 **observations 被清空为 0 条**——真实模型**从未看到任何工具返回的数据**。

模型 5 次决策全部合法、全部通过校验器、全部由真实 MiMo 产生，工具也返回了高质量真实数据
（咖啡因正确描述符、InChIKey、10 篇 Crossref 文献）。但"决策→工具→**观察**→解释→再决策"这条链在
"观察"这一环断了。模型诚实地反复报告"我看不到结果"，没有编造——这恰恰证明科学真实性约束生效，
但也证明**自主决策能力在真实工具集下无法被验证**。

## 6. 问题与改进建议

### 6.1 【M2.0 架构问题 — 严重】工具目录不参与状态预算，导致工具结果对模型不可见

**证据：**
- `agent/intelligence_prompt.py` 中 `STATE_BUDGET_CHARS = 24000`。
- `build_live_intelligence_stack()` 产生的 44 工具完整目录 JSON = **57577 字符**，单是目录就超预算 2.4 倍。
- `render_state` 的截断循环只遍历 `("decisions", "observations", "session_summaries", "facts")`，
  **`available_tools` 不在其中**，因此无法被削减。
- 循环在 `observations` 被 pop 空后退出，但总长仍 58016 > 24000，`state_truncated` 标记被写入。
- **实测：** 完整目录下 `render_state` 输出的 `observations` 条数 = **0**；
  目录仅保留 2 个工具时，`observations` = **1**，且能读到 `C8H10N4O2`。
- **量化佐证：** 5 轮输入 Token 仅净增 493，与"观测数据从未进入 prompt"一致。

**影响：**
- 直接击穿 M2.0 的核心承诺——"AI 根据实际工具结果决定下一步"。
- 工具越丰富（生产栈 44 个），缺陷越严重；这是**反规模**的。
- 本次验收的 B/C/D 类问题（循环、结果驱动改向）**因此无法验证**。
- 好的一面：模型行为诚实，未编造，科学真实性约束仍然成立。

**建议修复方向（本轮未改，待审阅）：**
1. **最小改动**：把 `available_tools` 加入截断循环，并让它**最后**被削减（观测数据优先保留）。
2. **更正确**：目录按本运行"已用到 + 可能用到"裁剪，而非全量 44 个；
   或目录单独占用一个预算池，与观测数据预算分离。
3. 补一条回归测试：**给定 N 个工具 + M 条 observation，rendered observations 数必须 == M**。
   现有 104 个 AI 测试全部用 1–4 个工具的小目录，因此完全未覆盖此缺陷——这是**测试设计不足**。

### 6.2 【M2.0 架构问题 — 中等】运行结果与报告无法跨进程读取

**证据：** 运行结束后在新进程调用 `application.report(session_id)` 抛
`SESSION_NOT_FOUND: no research session ... in this process`。
`_LiveRun` 只存于内存字典。

**影响：** `decision_records`（完整审计）与 `tool_results`/`observations`/`interpretations`
**只存在于启动进程内**。`StudyContext` 虽持久化了 5 条决策，但只有摘要文本，
不含 validator 裁决、token 用量、observation 原文。
本轮靠运行脚本自行 dump JSON 才保住完整记录。

**建议：** 这一点我在 M2.0 报告中写的是"暂停无法跨进程恢复"，措辞低估了范围——
实际是**报告与完整审计轨迹均不可跨进程读取**。建议把 `DecisionRecord` 作为 study artifact 持久化。

### 6.3 【工具能力不足 / 数据源】文献命中质量低 + OpenAlex 限流

**证据：** OpenAlex 返回 429（每日额度耗尽）；Crossref 返回 10 条，前三条均为
"Caffeine see Phenylpropanolamine/caffeine" 这类药物组合噪声条目，非合成方法学文献。

**影响：** 即使修好 §6.1，本轮也拿不到有价值的化学文献证据。

### 6.4 【测试设计不足】`build_live_intelligence_stack` 未注入 knowledge_base 时缺少提示
